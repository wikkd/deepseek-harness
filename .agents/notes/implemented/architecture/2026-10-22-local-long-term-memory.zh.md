# Agent Note: 本地、需同意的长期记忆

Status: implemented

[English](2026-10-22-local-long-term-memory.md) | 中文

## 问题

助手会在对话之间忘记持久的用户偏好与事实。消费级助手应当能记住用户明确要求记住的事情，例如喜欢的饮料或反复出现的约束；但保存个人笔记会引出同意、隐私、可见性与提示词预算等问题，而通用记忆插件并不回答这些问题。现有的第三方 `dsh-tool-memory` 把 Markdown 文件存在配置的根目录下，却没有首次运行同意门禁、可用性开关、结构化编辑界面，也无法在运行时撤下模型可见界面。

## 决策

长期记忆仅限本地、显式保存且需用户同意。全新安装以 `consented: false` 与 `enabled: false` 开始；在用户同意并开启之前，不存储任何条目，模型也看不到任何记忆工具或提示词区段。关闭会保留条目与同意，但在下一次组装请求时撤下工具与提示词区段。用户可以在设置的记忆页查看、新增、修改、删除、清空条目并切换开关。

该能力拆分为四个包。`@deepseek-ai/dsh-memory` 拥有条目词汇、同意状态、`ctx.memory` 服务与 `memory/settings-changed` 事件。`@deepseek-ai/dsh-memory-local` 从共享存储栈打开一个带版本的存储领域，把条目与同意存放在 `<DSH_HOME>/storages/memory.json`，串行化变更，并为生成的 `remote.memory` 命名空间装饰设置方法。`@deepseek-ai/dsh-tool-memory` 拥有 `memory_save`、`memory_search`、`memory_forget` 与有界提示词区段，并在每次设置变更时释放并重新注册该界面。`@deepseek-ai/dsh-client-ui-settings-memory` 拥有浏览器端的同意、开关与条目管理页。

提示词区段受 `maxPromptEntries`（默认 40）与 `maxPromptChars`（默认 4000）限制，记忆关闭或为空时省略。其标题把条目标记为关于用户的背景事实而非指令，并告诉模型当笔记与当前对话冲突时应询问。保存是显式的：模型必须在用户要求或清楚表达持久偏好后调用 `memory_save`。完全相同的文本会刷新已有条目，而不是创建第二行。

本地提供方在 Web profile 中取代第三方 `dsh-tool-memory`。记忆读写不发起网络请求，也不调用模型。设置页只通过生成的 Remote 命名空间访问提供方，因此浏览器从不直接读取 JSON 文件。

## 考虑过的替代方案

**保留第三方的 Markdown 文件记忆。** 不予采用，因为它没有首次运行同意门禁、可用性开关、结构化的修改/删除/清空界面，也无法在运行时撤下模型可见界面。它还与仓库规则冲突：产品功能应实现为 workspace 插件，而不是本地第三方集成。

**自动会话提取。** 首个版本不予采用，因为它会存储用户未明确选择的事实，使删除更难推理，并需要第二次模型调用及其自身的失败与隐私面。显式保存让持久状态与用户可见状态完全一致。

**嵌入或语义搜索。** 不予采用，因为它为小型个人存储增加模型或向量依赖、索引生命周期与新失败模式。`memory_search` 对文本与类型做不区分大小写的字面匹配，最多返回 20 条。

**在启动时通过系统提示词区段始终注入所有条目。** 不予采用，因为关闭的记忆仍会模型可见，且每个条目都会消耗提示词预算。动态注册加上两个配置边界，让关闭行为诚实且提示词成本可预测。

**存放到 `~/.dsh/memories` 或 profile 相对的 Markdown 文件。** 不予采用，因为产品数据目录隔离规则（`~/.xiaoyuan`，可由 `DSH_HOME` 覆盖），也因为应复用现有的带版本存储领域，而不是另建临时文件格式。

## 后果

记忆是未加密的本地 JSON，因此产品不声称静态加密。变更在单个 Host 进程内串行；共享同一数据目录的两个应用实例不受协调。精确文本去重不会合并改写后的表述，条目上限会拒绝新保存，而不是驱逐较旧条目。工具描述劝阻保存秘密，但提供方与设置页都不会分类或拒绝它们。

开启、关闭、新增、修改或删除条目会改变下一次组装请求中的提示词区段或工具集，可能使该点之后的前缀复用失效。未变化的记忆界面仍可缓存。包拆分还让约定、存储、模型界面与设置页可以分别测试，并让浏览器无需导入 Host 存储代码。

记忆设置页是 `@deepseek-ai/dsh-api-remotes` 中生成的 `remote.memory` 贡献的第一个消费方；修改 Remote 方法或快照字段时，必须在同一变更中重新生成该贡献、工具目录与双语包文档。
